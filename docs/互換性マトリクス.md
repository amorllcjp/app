## 「対応済み」の定義

以下をすべて通過したクライアントにだけ「対応済み」を付ける。1つでも未確認なら「接続確認のみ」。

1. 認証（正しいトークンで通る／誤ったトークンで 401）
2. ツール一覧の取得（5ツールが見える）
3. 検索が出典つきで返る
4. エラー時の挙動（存在しない chunk_id 等）
5. 長文の応答（大きい Pack のエクスポート）
6. タイムアウト
7. 再接続

クライアントやプロトコルの変更で壊れた場合、状態を「要再検証」へ戻す。

### サーバー側で確認済みのこと（クライアント非依存）

ローカルで curl により確認（2026-08-04）。**本番URLでの確認ではない。**

| 項目 | 結果 |
|---|---|
| 2025系プロトコル（通常の JSON-RPC POST） | 動作 |
| 2026-07-28系（`Mcp-Method` / `Mcp-Name` ヘッダ + `_meta` エンベロープ） | 動作 |
| 認証なしのリクエスト | 401。ツール一覧も返さない |
| 誤ったトークン | 401 |
| `context_search` の出典 | Pack名・タイトル・URL・由来・取得時刻がすべて付く |
| `context_save`（`confirm=false`） | 保存しない |

### Codex の詳細（2026-08-04）

| 項目 | 結果 |
|---|---|
| 1. 認証 | ✅ 通過 |
| 2. ツール一覧 | ✅ 5ツールすべて見える |
| 3. 検索が出典つきで返る | ⬜ **未検証**。Pack の収録資料が0件だったため 0件応答。検索機能の可否は判定できていない |
| 4. エラー時の挙動 | ✅ `chunk_id=999999` で「見つかりません」 |
| 5. 長文の応答 | △ エクスポートは末尾まで返ったが、資料0件のため長文にはなっていない |
| 6. タイムアウト | ⬜ 未検証 |
| 7. 再接続 | ✅ 30秒放置後に正常応答 |

**3 が通るまで「対応済み」にはしない。** これが製品の中核だから。

この検証で見つかった製品側の問題（修正済み）:
- 資料0件でも空の Pack を作れ、AI を接続でき、0件を返すだけで
  「資料が無いこと」を伝えていなかった。検索語の問題と区別できず、利用者が詰まる。
  → `context_search` / `context_pack_status` / 画面の3か所で、
    「資料0件」と「一致しない」を区別して案内するようにした。

## 次に確認すること

Codex を「対応済み」に上げるには、実際の Codex から以下を試す。

```
1. context-bridge のツールを一覧して
2. context-bridge で「単価」を検索して、出典つきで教えて
3. context-bridge の chunk_id 999999 の根拠を取得して   → 「見つかりません」が返ること
4. context-bridge で Pack を Markdown で出力して          → 長文応答が壊れないこと
5. （しばらく放置してから）もう一度検索して               → 再接続できること
```

結果をこの表に追記する。**通らなかった項目は空欄にせず、通らなかったと書く。**
