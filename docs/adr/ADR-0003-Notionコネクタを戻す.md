# ADR-0003: Notion コネクタを戻す（ADR-0001 D1 の取り消し）

日付: 2026-08-04
状態: 採用
関連: [ADR-0001 削除した要件](ADR-0001-削除した要件.md) の D1

## 何を変えるか

ADR-0001 で削除した Notion コネクタ（D1）を復活させる。

## なぜ削ったか（当時の判断）

> OAuthアプリ登録・審査が他者依存で、着手から利用可能までの時間が読めない。無くても価値仮説は検証できる。

**技術リスクの評価としては正しかった。** 実際、コネクタ無しで MVP を出し、
本番で「日本語検索 → 出典つき応答」の連鎖が通ることを確認できた（互換性マトリクス参照）。

## なぜ戻すか（判明したこと）

**削ったのは「連携機能」ではなく「入力の物語」だった。**

MVP を実際に使う段になって、次の問いに答えられないことが分かった。

> **どういう時にデータを入れるのか。**

読み出す場面は自然に想像できる（「あの案件の検収条件は」）。
しかし入れる場面が無い。誰も「よしコンテキストを整備するか」とは思わない。
入力は未来の自分への投資で、リターンが不確実だから続かない。

これは記録系ツール全般の根本問題であり、**手で貼らせる設計では解決しない。**

自動同期があれば、この問いが消える。**すでに Notion に書いてあるものが勝手に入る。**
入力の動機がゼロで済む。これが Notion コネクタの本当の役割だった。

### 判断の誤り

ADR-0001 では、コネクタを「価値の核ではない付加機能」と分類した。
実際には**価値の核へデータを供給する唯一の現実的な経路**だった。

技術リスク（審査・API・保守）だけで判断し、**製品として成立するかを見ていなかった。**
削除の基準に「これが無いと利用者は何をすればよいか分かるか」を入れていれば防げた。

## 何を作るか

### v1（この ADR の対象）

1. Notion の OAuth 接続。ページ選択は Notion 側の画面に任せる
2. 選択されたページを取得し、Markdown に変換して Pack へ入れる
3. **手動の「同期」ボタン**。1回押せば全ページが入る
4. 差分取得（`last_edited_time` を見て、変わったものだけ入れ直す）
5. 削除検出（Notion 側で消えた／共有解除されたページを索引から外す）

手で貼るのと比べて、**資料1件ごとのコピペが消え、Pack 単位で1クリックになる。**

### v2（v1 が動いてから）

定期同期。Vercel Cron を使う。ここまで来ると入力の動機が完全にゼロになる。

## 戻さないもの

ADR-0001 の他の削除項目はそのまま。特に:

- **Chatwork（D2）** — API 条件が未確認のまま。Notion が効くと分かってから
- **埋め込み検索（D5）** — 語検索で足りている
- **同期状態の6状態（D6）** — v1 は `未同期 / 同期中 / 完了 / 失敗` の4つに絞る。
  要件書 FR-005 の完全版は、実際に必要になってから

## 守る不変条件（変えない）

コネクタを足しても、これらは一切緩めない。

- 出典を持たない検索結果は返さない。Notion 由来なら**そのページのURL**が出典になる
- 取得時刻を必ず表示する。「常に最新」とは言わない
- ユーザーが選んだページだけを取り込む。ワークスペース全体を勝手に読まない
- Notion 側で削除・共有解除されたら索引から外す

## 前提条件（利用者側の作業）

**Notion の Public Integration 登録が必要で、これは実装では代替できない。**

- Notion の Integrations 画面で Public integration を作成
- Redirect URI に `https://<本番URL>/connect/notion/callback` を設定
- `NOTION_CLIENT_ID` と `NOTION_CLIENT_SECRET` を環境変数に設定

登録が通らない、または条件が合わない場合は v1 を中止し、手動貼り付けのまま
「議事録を書く習慣がある人」に対象を絞る（前回の選択肢 B）。

## 見直す条件

- Notion 連携を入れても、実データが Pack に貯まらない
  → 入力の物語の問題ではなく、そもそも需要が無い。要件書 §17 に戻る
- Notion API の制約（レート制限、取得できるブロック種別）で実用に足りない
  → 対象ソースを変える

---

## 追記（2026-08-09）: 前提が外れた

利用者に確認した結果、**案件情報を Notion にどこにも書いていない**ことが分かった。

このADRは「自然にデータが入る流れ＝Notion 連携」という前提で書いたが、
その前提は本人に対して成立しない。既存の資料が無い相手に「既存の資料をつなぐ」
機能を出しても、Pack は空のままになる。

### 判断

1. **Notion コネクタは残す。削らない。**
   Notion に案件情報を書いている利用者には有効で、実装も検証も済んでいる。
   ただし**主役から降ろす**。ダッシュボードでは畳んだ状態で出す。
2. **入力の物語を差し替える。**
   本線は `context_save`（AIとの会話の途中で保存する）。
   理由: 利用者がどこにも書いていなくても、**AIには喋っている**。
   すでに起きている行為に乗るので、新しい習慣を要求しない。
   連携設定・OAuth登録・トークン発行のいずれも不要。
3. Notion の Public Integration 登録（上記「前提条件」）は**保留**。
   本人が Notion を使っていない以上、いま払うコストではない。

### 確認したこと（ローカル、2026-08-09）

| 確認 | 結果 |
|---|---|
| MCP経由 `context_save`（confirm=true） | 保存された（provenance: `user_saved`） |
| MCP経由 `context_save`（confirm=false） | 拒否。「利用者に確認してください」を返す |
| MCP経由 `context_search` で読み出し | 出典・取得時刻つきで1件返った |

入力から出力までの輪が、外部連携なしで閉じていることを実測で確認した。

### 見直す条件（差し替え）

- `context_save` の利用が伸びない
  → 「AIに喋っている」という前提自体が誤り。要件書 §17 に戻る
- 保存はされるが読み出されない
  → 貯める価値が無いということ。Pack の粒度か対象業務を変える
