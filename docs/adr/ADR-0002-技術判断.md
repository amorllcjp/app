# ADR-0002: 技術判断（検索・MCP・認証）

日付: 2026-08-03
状態: 採用

## 1. 日本語検索を自前のbigram索引で行う

### 測定した事実

| 方式 | 「請求書」(3文字) | 「単価」(2文字) | 「田中」(2文字) |
|---|---|---|---|
| PostgreSQL `to_tsvector('simple')` | 語分割できず不可 | 不可 | 不可 |
| SQLite FTS5 `trigram` トークナイザ | ヒット | **0件** | **0件** |
| 自前bigram索引 + 実体再チェック | ヒット | ヒット | ヒット |

FTS5 の `trigram` は3文字のグラムを作るため、2文字のクエリからはグラムが1つも生成されず、
何にも一致しない。日本語の業務語は2文字が多い（単価、面談、請求、稟議、検収）ため、
これは実運用で致命的になる。

### 採用した方式

pg_bigm と同じ二段構えにした。

1. 本文を2文字の重なりグラムに展開して FTS5 に入れる
2. クエリも同様に展開し AND で候補を引く
3. **候補の原文に対して、クエリ文字列そのものを含むか再チェックする**

3 が無いと「東京」「京都」を含むが「東京都」とは書かれていない文書が誤ってヒットする。
この偽陽性はテストで固定している（`test/core.test.ts`）。

### 結果

PostgreSQL と拡張のインストールが不要になり、SQLite 単体で日本語検索が成立した。

### 見直す条件

- 語検索での正解率が評価セットで目標に届かない
- 同時書き込みが増え、SQLite が律速になる

## 2. MCP は SDK v2 を使い、両世代を1つの定義で serve する

### 確認した事実

- v2 のパッケージ名は `@modelcontextprotocol/server` / `@modelcontextprotocol/client`（各 2.0.0）。
  従来の `@modelcontextprotocol/sdk` は 1.30.0 が最新で 2.x は存在しない
- `createMcpHandler` の既定 `legacy: 'stateless'` により、**2025系クライアントと
  2026-07-28系クライアントの両方が、同じツール定義で動く**

### 実機で確認した動作

| 世代 | リクエスト形式 | 結果 |
|---|---|---|
| 2025系 | 通常の JSON-RPC POST | 動作 |
| 2026-07-28系 | `MCP-Protocol-Version` + `Mcp-Method` + `Mcp-Name` ヘッダ + `params._meta` エンベロープ | 動作 |

2026-07-28系は、ヘッダとボディの整合を厳密に検査する。ヘッダが欠けると
`-32020 Bad Request` を返し、何が足りないかを名指しで教えてくれる。

### 意味

要件書 §7.1 が想定していた「旧クライアント互換を別途作る」作業は不要だった。
互換性マトリクス（FR-015）は、実際に接続したクライアントの記録として引き続き必要。

## 3. MCP認証は Bearer トークンにする（要件書からの意図的な逸脱）

### 逸脱の内容

要件書 §7.1 は「OAuth/OIDC のディスカバリ、PKCE、issuer検証を満たす実装」を求めている。
MVPではワークスペース単位の Bearer トークンにした。

### 理由

Bearer でも、検証したいこと（クライアントが繋がるか／課金が成立するか）は検証できる。
OAuth 一式は実装量が大きく、それを先に作ると最初の顧客に会うのが遅れる。

### 現状の防御

- トークンの平文は保存せず SHA-256 ハッシュのみ保持。発行時に一度だけ表示
- 再発行で旧トークンは即時失効（テストで固定）
- トークンはワークスペースに束縛。他ワークスペースは一切見えない（テストで固定）
- 認証できないリクエストにはツール一覧すら返さない（401）

### 返済条件

以下のいずれかで OAuth に移行する。

- 複数人で1ワークスペースを使う要求が出た（トークン共有が起きる）
- 顧客のセキュリティレビューで OAuth が要件として提示された
- MCPクライアント側が Bearer ヘッダ設定を廃止した

## 4. 保存は SQLite 単一ファイル

同時利用が50ワークスペース程度（要件書 §11.2 の初期目標）までは単一ファイルで足りる。
WAL を有効化している。バックアップはファイルコピーで済む。

見直す条件: 書き込みの競合が観測された時、または複数プロセスで動かす必要が出た時。
