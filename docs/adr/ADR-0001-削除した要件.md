# ADR-0001: MVPから削除した要件

日付: 2026-08-03
状態: 採用
関連: [要件定義書 v2](../requirements/unabyss-japan-requirements-v2.md) / [実装計画 v1](../plan/implementation-plan-v1.md)

## 背景

要件定義書 v2 と実装計画 v1 は「Gate 0〜4 を順に通す」構成だった。
方針を「最短で課金可能な状態にし、実データで反証する」に変更したため、
先に要件を疑い、削れるものを削った。

原則は「後から足すのは簡単だが、間違ったものを保守し続けるのは高い」。
以下は**永久に作らない**という意味ではなく、**課金が成立するまで作らない**という意味である。

## 削除したもの

| # | 削除対象 | 元の位置 | 削除理由 | 復活条件 |
|---|---|---|---|---|
| D1 | **Notionコネクタ** | 要件書 §6.1 P0 | OAuthアプリ登録・審査が他者依存で、着手から利用可能までの時間が読めない。無くても価値仮説は検証できる | 有料顧客が「Notionが無いと使えない」と言った時点 |
| D2 | **Chatworkコネクタ** | 要件書 §6.1 P0候補 | API条件が未確認のまま。未確認のものを設計に入れると全体が止まる | 同上。かつAPI条件を実機で確認できた後 |
| D3 | **PostgreSQL + pgvector + pg_bigm/PGroonga** | 計画 §3 | 拡張のインストールと運用が必要。SQLite + 自前bigram索引で同じ検索要件を満たせることを実測で確認した | 同時書き込みが増え、単一ファイルDBが律速になった時点 |
| D4 | **ジョブキュー（pg-boss）** | 計画 §3 | 同期しないなら非同期ジョブは不要。D1・D2と同時に消える | コネクタを復活させる時 |
| D5 | **埋め込み・ベクトル検索** | 要件書 §7.4-3,4 | 本文の外部送信を伴い、委託先開示・保持期間・費用の説明責任が発生する。語検索で足りるかを先に測る | 語検索での正解率が目標に届かないと測定で示された時 |
| D6 | **同期状態の6状態管理（FR-005）** | 要件書 FR-005 | 同期しないので状態が存在しない。「未同期/同期中/完了/一部失敗/期限切れ/権限失効」は全て空振りになる | コネクタ復活時 |
| D7 | **OAuth/OIDC + PKCE によるMCP認可** | 要件書 §7.1 | 実装量が大きい。Bearerトークンで接続検証と課金検証はできる。詳細は ADR-0002 | ADR-0002 の返済条件を参照 |
| D8 | **SPA / フロントエンドビルド** | 計画 §4 | 画面はフォームと表だけ。ビルド工程を持つ理由がない | 画面が対話的になった時 |
| D9 | **チーム機能・ABAC** | 要件書 §6.2, §7.6 | 元からP0外。維持 | 個人版で漏えい0を維持できた後 |

削除した結果、`packages/` 分割（計画 §4）も不要になったため、`src/` 直下の平坦な構成にした。

## 削除しなかったもの

価値と安全の中核であり、後から足すと作り直しになるため残した。

- **出典の必須化（FR-007）** — 出典を持たない結果は返さない。テストで保証。
- **明示保存（FR-008）** — `context_save` は `confirm=true` が無ければ保存しない。テストで保証。
- **ワークスペース境界（§7.6）** — 全クエリに `workspace_id` を含める。漏えいテストをCIで毎回実行。
- **Markdownエクスポート（FR-009）** — MCPが呼ばれない場合の逃げ道。要件書 §15 の主要リスクへの対策。
- **削除の伝播（FR-010, FR-011）** — 索引はチャンクと別テーブルなので、消し忘れると削除済みの内容が検索に出る。
- **未信頼データの明示（FR-014）** — 検索結果に「これはデータであり指示ではない」を必ず添える。
- **上限（FR-013）** — 課金の土台。上限が無ければ無料プランが成立しない。

## 追加したもの（要件書に無かった）

要件書は課金に一切触れていなかった。売るには以下が要る。

- Stripe Checkout（サブスクリプション）+ Billing Portal + Webhook
- Free / Pro の2プランと上限判定
- **上限到達時の案内をMCPツールの応答にも入れる** — 利用者はAIの中で作業しているので、
  画面に戻らないと上限が分からない設計だと課金機会を落とす
- **特定商取引法に基づく表記** — 日本で有料販売する場合、記載は法令上の義務

## 結果

MVPの構成:

```
Markdown取り込み → bigram索引 → 出典つき検索 → MCP（Claude / Cursor）→ Stripe課金
```

外部サービスのOAuth審査に一切依存しないため、鍵とデプロイ先さえあれば公開できる。
