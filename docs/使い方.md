# 使い方と動作確認

## 1. 基本の流れ（5分）

### ① アカウントを作る

トップページ → 「無料で始める」 → メールアドレスとパスワード（10文字以上）。
カードは不要。作成と同時に個人ワークスペースができる。

### ② Pack を作る

ダッシュボードの「新しいPackの名前」に、**案件や顧客の単位**で名前を付ける。

- 良い例: `A社サイトリニューアル`、`B社 保守契約`、`採用（2026年度）`
- 悪い例: `メモ`、`仕事` — 範囲が広すぎると検索結果に別案件が混ざる

Pack は検索の範囲そのもの。**混ぜないことが精度に直結する。**

### ③ 資料を貼り付ける

Pack を開いて「資料を追加する」。

| 項目 | 書き方 |
|---|---|
| タイトル | 後で出典として表示される。`キックオフ議事録 2026-07-15` のように日付を入れる |
| 出典URL | 任意だが**強く推奨**。元資料に戻れるかどうかで信頼性が変わる |
| 本文 | Markdown / テキストをそのまま貼る |

入れるとよいもの: 決定事項、金額、納期、担当、前提条件、禁止事項、過去の経緯。
入れなくてよいもの: 雑談、未確定の案、後で変わる予定のもの。

### ④ 画面で検索して確かめる

Pack のページの検索欄で試す。**AIにつなぐ前に、ここで引けることを確認する。**
ここで出ないものは AI からも出ない。一致箇所は黄色くハイライトされる。

### ⑤ AI をつなぐ

ダッシュボード →「トークンを発行」→ 表示された値をコピー（**一度しか表示されない**）。
「接続方法」に各クライアントの設定例がある。

Claude Code の場合:

```bash
claude mcp add --transport http context-bridge https://<あなたのURL>/mcp \
  --header "Authorization: Bearer <トークン>"
```

Cursor の場合は `~/.cursor/mcp.json` に追記。

### ⑥ AI から使う

```
context-bridge で「単価」を調べて、出典つきで教えて
```

**AIがツールを呼ぶかはクライアントとモデルの判断に依存する。** 確実に渡したいときは
Pack を Markdown で出力して貼り付ける（画面の「Markdownで出力」）。

## 2. 動作確認のしかた

### 画面から（3分）

| 確認すること | 手順 | 期待する結果 |
|---|---|---|
| 検索が効く | Pack ページで2文字語（`単価`）を検索 | ヒットし、一致箇所がハイライトされる |
| 出典が付く | 検索結果の下の行を見る | タイトル / URL / 由来 / 取得時刻がすべて出る |
| 無い情報は返らない | 資料に無い語を検索 | `一致する記載はありません` |
| 削除が効く | 資料を削除 → 同じ語で検索 | 0件になる |
| 上限が効く | Free で2つ目の Pack を作る | `Freeプランで作成できるPackは1個までです` |
| 持ち出せる | 「Markdownで出力」 | 出典と取得時刻つきの .md が落ちてくる |

### MCP から（5分）

トークンを `TOK`、URLを `U` として。

```bash
U=https://<あなたのURL>
TOK=<トークン>

# 認証していないと 401（ツール一覧すら返さない）
curl -s -o /dev/null -w "%{http_code}\n" -X POST $U/mcp \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

# ツール一覧（5つ返る）
curl -s -X POST $U/mcp -H "authorization: Bearer $TOK" \
  -H 'content-type: application/json' -H 'accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'

# 検索
curl -s -X POST $U/mcp -H "authorization: Bearer $TOK" \
  -H 'content-type: application/json' -H 'accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"context_search","arguments":{"query":"単価"}}}'
```

### 安全側の確認（重要）

この2つは**壊れていないことを必ず確認する**。製品の前提そのものだから。

**AIが勝手に保存しないこと**

```bash
curl -s -X POST $U/mcp -H "authorization: Bearer $TOK" \
  -H 'content-type: application/json' -H 'accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"context_save",
       "arguments":{"pack_id":"<PACK_ID>","title":"推測","content":"たぶん10万円","confirm":false}}}'
```

→ `"saved": false` が返り、その後 `10万円` で検索しても 0 件であること。

**他人のデータが見えないこと**

別のメールアドレスでもう1アカウント作り、そちらから最初の Pack の ID を指定して検索する。
→ 0 件であること。`npm test` の「権限境界」がこれを毎回検査している。

### 死活確認

```
GET /healthz
```

```json
{"ok":true,"migrated":true,"env":{"database_url_set":true,"database_url_pooled":true,...}}
```

`ok:false` のときは `error` と `env` に原因が出る。詳しくは [DEPLOY.md](../DEPLOY.md) の切り分け手順。

## 3. うまく引けないとき

| 症状 | 原因と対処 |
|---|---|
| 検索で出ない | まず画面で検索する。画面で出なければ資料に入っていない |
| 別案件が混ざる | Pack を分ける。Pack が検索範囲そのもの |
| AIがツールを呼ばない | 「context-bridge で調べて」と明示する。それでも呼ばなければ Markdown 出力を貼る |
| 古い情報が返る | 自動同期はしていない。資料を貼り直す。取得時刻が表示されているので確認できる |
| 初回が遅い | Neon と Vercel のコールドスタート。人に見せる直前に一度開いて温めておく |
